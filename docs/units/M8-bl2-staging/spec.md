# M8-bl2-staging — spec

**Milestone:** M8 (the full boot chain, stage C; first unit). **Requirements:** REQ-SYSC-002 (boot source from `SYS_LSI_MODE`, proven when the real BL2 reads it), REQ-GUEST-003 (unmodified firmware). **Status:** implemented.

One page. Facts carry their source; inferences and assumptions are labelled (I) / (A). The contract, the image layout and BL2's accesses are in [`research/bl2.md`](../../research/bl2.md).

## Scope

The board's own TF-A BL2, built from the vendor source, starts from the module's QSPI flash and runs until it first needs the DDR memory controller (the next unit, M8-ddr-stub).

- **Guest builds** (project, `tests/guests/fw/`): `build-tf-a.sh` also builds `bl2` and `fiptool` with the same flags as BL31 (`PLAT=v2l BOARD=smarc_2 SPD=opteed DEBUG=0`); a new `build-spi-image.sh` writes a 64 MiB flash image: the 512-byte boot parameter block from TF-A's own `bptool` at `0x0`, `bl2.bin` at `0x200`, a FIP (`bl31.bin`, OP-TEE `tee-raw.bin`, `u-boot.bin`) at `0x20000`, `0xFF` elsewhere (`research/bl2.md` §2). Each records its command and output hashes, as the other firmware builds do.
- **Boot-ROM stand-in** (fork `hw/arm/rzv2l-smarc.c`; spec §12 stage C: no ROM model): with `boot-mode=3` or `4` (serial flash, manual Table 4.1 p.105) and neither `-bios` nor `-kernel`, at every machine reset the board reads the flash drive's size block, checks the `0xAA55` signature, copies `size` bytes from flash `0x200` to on-chip RAM `0x12000`, and starts core 0 there at EL3 in AArch64, core 1 off (manual §4.2.4.3-4.2.4.4 p.128-129). No drive, a missing size block or signature, a size of zero or above `0x1D000`, an image shorter than the size, or a drive read failure stop QEMU with an error that names the cause (the ROM's fallback, SCIF download mode, is not modelled). The CPG and the SPI controller start at their reset values (A). This differs from the ROM, which turns on the SPI controller's clock and releases its reset (manual §4.2.4.2 step 1); BL2 sets both up itself before it uses the controller (`research/bl2.md` §1). With `-bios` the M7 path (QEMU in BL2's place) is unchanged.
- **CPG** (fork `hw/misc/renesas_rzv2l_cpg.c`, FUNCTIONAL): `CPG_SAMPLL4_STBY`/`_CLK1`/`_CLK2`/`_MON` (`0x010`-`0x01C`) and the same for PLL6 (`0x020`-`0x02C`) with the reset values of Table 7.5 (p.246). STBY is written through its write-enable bits (§7.2.4.1 p.252-253); CLK1 and CLK2 are ordinary 32-bit registers whose upper bits are data (CLK1 `DIV_K` 31:16; CLK2 bits 31:24, 15:14 and 7:3 reserved, §7.2.4.2-7.2.4.3 p.254-257). Each `MON`'s `RESETB` (bit 0) and `LOCK` (bit 4) follow `STBY.RESETB` at once (§7.2.4.4 p.259; I: no lock time, BL2 checks none). The SRC clock and reset registers `0x574`, `0x6F4`, `0x874`, `0x9F4` as their siblings (I: write-enable halves, `CLKON` and `RST` reset 0, so `CLKMON` reads 0 and `RSTMON` bit 0 reads 1; the deleted manual entries give no values).
- **SYSC** (fork `hw/misc/renesas_rzg2l_sysc.c`, register file, not enforced): `SYS_MSTACCCTL0`-`5` and `SYS_SLVACCCTL0`-`15` stored with the reset values of Table 6.1 (p.167-168), Secure accesses only; a Non-secure access is refused like the TZC's. Every bit is stored (A: the reserved bits are not masked; BL2 masks its own read-modify-writes). Table 6.1 lists `SLVACCCTL6` at `H'0114`, `SLVACCCTL5`'s address; TF-A puts it at `0x118` (`include/sys_regs.h:24`), and so does the model (a manual erratum, recorded). On the board a Non-secure read of `MSTACCCTL0` and of `SLVACCCTL0` aborts (O, `research/sysc.md`); the same rule for the rest of the bank is an inference (I). Device map gap 9 (not enforced) stays open.
- **Two start states.** Firmware mode: the manual reset values above. Direct-kernel mode and the M7 BL2 stand-in (`cpg_post_firmware`, `cpg_post_bl2`): PLL4 and PLL6 in normal mode with BL2's settings (`cpg_pll4_setdata`, `cpg_pll6_setdata`, `cpg.c`; I: what BL2 writes, not measured), the SRC registers as BL2's tables leave them (stopped and in reset: their reset values). The SYSC access-control registers keep Table 6.1's values in every start state: BL31 does not touch them (`P/plat_security.c:134-168`) and no Non-secure guest can read them.
- **Source conflict, recorded:** the manual's revision history (p.3554) lists `CPG_CLKON_SRC` and `CPG_RST_SRC` as deleted (their old section numbers, 7.2.4.55 and 7.2.4.134, now hold the USB clock and I2C reset registers); BL2 writes and polls them (`cpg.c:254-255`, `:450-451`). Guest code rules what is required; the model keeps them as ordinary clock and reset registers.
- **Not modelled:** the boot ROM itself (its SCIF fallback, its SPI and CPG settings, its I/O buffer set-up), PLL lock time, the SSCG modulation, enforcement of the access-control registers, `SLVACCCTL9`/`11`/`15` beyond storing what is written (no manual row; A: reset 0).

## What the guest needs

BL2 (TF-A `f59ed5a31`), in order: EL3 entry at `0x12000` (`bl2/aarch64/bl2_el3_entrypoint.S`); `cpg_early_setup()` and `cpg_setup()`: PLL4/PLL6 standby poll, set-up, lock poll (`P/drivers/cpg.c:756-790`), dividers, clock-on and reset tables with monitor polls including SRC (`:240-470`, `:888-936`); `pfc_setup()` (`P/drivers/pfc.c:168-264`); the SCIF0 console; `NOTICE: BL2: v2.10.5(release):...` and the build line (`bl2/bl2_main.c:95-96`); `bl2_platform_setup()`: TZC-400 set-up for DDR and SPI, then the SYSC access-control read-modify-writes (`P/plat_security.c:19-132`); then `ddr_setup()` (`P/drivers/ddr/ddr.c:73`), the next unit's.

## Exit criterion

- `-M rzv2l-smarc,boot-mode=3 -drive if=mtd,format=raw,file=spi.img` (no `-bios`, no `-kernel`): SCIF0 prints `NOTICE:  BL2: v2.10.5(release):2.10.5/rz_1.1.0` and `NOTICE:  BL2: Built : f59ed5a31` (the project's build, as its BL31); BL2 passes its security set-up and stops at its first DDR controller or PHY access, which the `-d unimp,guest_errors,invalid_mem` log names (the next blocker). No other unlisted line in the log.
- The ROM stand-in's errors: no drive, a bad signature, a zero or oversized loader size: each stops QEMU with its message, and a size of exactly `0x1D000` boots (acceptance). An image shorter than the flash, and with it a short loader or a drive read failure, is stopped before the stand-in runs: the flash model (`m25p80`) refuses a drive of the wrong size and reads the whole drive when it starts; the stand-in's own checks for these remain as a guard.
- qtests: the PLL4/PLL6 and SRC reset values and monitor rules, the SYSC access-control reset values and the Non-secure refusal; each seen red under a mutation.
- M7 acceptance (with M1-M6) unchanged.

## Next blocker (fork `74752923ce`)

BL2 prints its banner (`NOTICE:  BL2: v2.10.5(release):2.10.5/rz_1.1.0`, `NOTICE:  BL2: Built : f59ed5a31`), passes its CPG, pin and security set-up (no log line from the TZC or SYSC), and its first DDR access stops it: `Invalid write at addr 0x11400200, size 4` in the `-d invalid_mem` log, a write to the DDR PHY, which has no window (layer verified: the memory map; the write is `disable_phy_clk()`, initialisation step 9, which `ddr_setup()` hands to `cpg_active_ddr()` before any controller access: `P/drivers/ddr/ddr.c:83`, `:482-487`). BL2 then waits without a print (its crash console is empty). The next unit, M8-ddr-stub, models the PHY and the memory controller (`research/bl2.md` §6); `bl2.py` now checks BL2's run to `Booting BL31` in place of this stop. Coverage before the stop (`-d unimp,guest_errors,invalid_mem`): the PFC logs BL2's 64-bit stores to its drive, slew, pull and input-enable registers and 32-bit stores to `SD_ch0`/`SD_ch1` (wider than the manual's access sizes; the silicon takes them; listed in `tests/acceptance/m8/expected/log-allow.txt`); nothing else.
