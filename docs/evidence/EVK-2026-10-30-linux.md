# EVK Linux view and watchdog reset registers — 2026-10-30

**Board:** RZ/V2L SMARC EVK (2 GB variant), console SCIF0 at 115200 8N1.
**Image:** EDGE AI OS 0.1.0, built by [edge-ai-yocto](https://github.com/umair-as/edge-ai-yocto) (the operator's public Yocto project for this board) on the Renesas BSP: a G2 image. Kernel `6.12.59-cip14-yocto-standard-gfb76169f9315` (rz_linux-cip `rz-6.12-cip14` plus that project's patches). Firmware banners as in [`EVK-2026-10-29-post-firmware.md`](EVK-2026-10-29-post-firmware.md): BL2/BL31 `v2.10.5(release):2.10.5/rz_1.1.0-dirty` (built Sep 25 2025), OP-TEE `82a5cd3b-dev`, U-Boot 2024.07 (built Sep 22 2025). Same firmware.
**Stages:** (A) Linux root shell, booted from eSD, RAUC slot B; (B) a Linux `reboot`, captured to the login prompt; (C) U-Boot prompt after a Linux `reboot`, autoboot stopped by the operator.
**Method:** read-only commands only. A: `cat` of `/proc` and `/sys`, `dmesg`. C: one `md.l`, with the deny list of AGENTS.md "Hardware oracle". The reboot in B and C rewrote the U-Boot environment, as every boot of this image does. The raw console output is kept by the operator.

All values are **hardware observations (O)** for this image. G2 differences (this image's own patches) are marked G2: they are not in the vendor DTB (DTB-V) and are not modelled.

## 3. The watchdog (A, B)

- systemd drives `/dev/watchdog0` = WDT0 (`12800800.watchdog`): `Watchdog running with a hardware timeout of 30s`; at shutdown `systemd-shutdown` sets 1 min. `watchdog1` (WDT1) exists and is not opened.
- U-Boot: `WDT: Started watchdog@12800800 with servicing every 1000ms (60s timeout)` (matches EVK-R40).
- During the reboot: `watchdog: watchdog0: watchdog did not stop!` (systemd hands the running watchdog to the next boot).

## 5. Firmware and reserved memory (B)

- PSCI: `PSCIv1.1 detected in firmware`, `SMC Calling Convention v1.4` (device map gap 1: QEMU's built-in PSCI reports v1.0).
- Reserved memory, all **G2**: CMA 256 MiB at `0x58000000`, `linux,multimedia` 128 MiB at `0x68000000`, `drp-ai` 512 MiB at `0x80000000`, `image-buf` 64 MiB at `0xb0000000`, ramoops 256 KiB at `0xbffc0000`.

## 6. CPG watchdog reset registers (C)

| ID | Measured | Expected (`requests.md`) | Result |
|---|---|---|---|
| EVK-R73 | `md.l 0x11010b10 2`: CPG_WDTOVF_RST `0x00000001`, CPG_WDTRST_SEL `0x0000008f` | `0x0` / `0x8F` | WDTRST_SEL MATCH (the model's direct-mode value). WDTOVF_RST = WDT0: the read followed a Linux `reboot`, so a reboot on this board ends in a WDT0 reset |

The mechanism of that reset is TF-A's PSCI `SYSTEM_RESET`, which forces a WDT0 parity error (code-derived; `../research/boot-chain-firmware.md`). In the model's direct mode QEMU's built-in PSCI resets the machine itself, so the flag stays 0 until a real BL31 runs (M7).

## 8. The SD hosts as Linux runs them (A)

At the same root shell as §7 (`dmesg`, `/proc/interrupts`, debugfs `mmc0/ios`, `mmc1/ios`, `/sys/block/mmcblk0`), no side effects. Question: what card and bus mode does SDHI0 run on the EVK, and does SDHI1 carry a card?

| Item | EVK |
|---|---|
| SDHI0 card | `mmc0: new high speed SDXC card at address aaaa`; `mmcblk0: mmc0:aaaa SR128 119 GiB`; partitions p1-p4 (`/sys/block/mmcblk0/device/type` = `SD`) |
| SDHI0 bus | 50 MHz (actual 50 MHz), 4-bit, timing `sd high-speed`, signal voltage 3.30 V, vdd 3.3-3.4 V, driver type B |
| SDHI0 host | `renesas_sdhi_internal_dmac 11c00000.mmc: mmc0 base at 0x0000000011c00000, max clock rate 100 MHz` |
| SDHI1 | probed (`max clock rate 100 MHz`), clock 0 Hz, vdd invalid: no card, slot powered off |
| Interrupts | `11c00000.mmc` INTID 136 (SPI 104): 85134; INTID 137 (SPI 105): 0; `11c10000.mmc` INTID 138, 139: 0. All level |
| Block queue | `max_segments` 1, `max_hw_sectors_kb` 4194303 |

So on this board the SD0 node (described as an 8-bit eMMC with HS200 in the DTB) runs a plain SD card at high speed, 4-bit, 3.3 V: no UHS, no tuning. The second SDHI0 line (SPI 105, the SDIO interrupt) never fires. Whether the transfers took the internal DMAC or the PIO fallback is not visible from these reads.
